# Heartbeats and recovered deadlines used different clock origins

Date: 2026-09-17. Design: §2.6, §4.4 leases, §4.14 daemon.alive, T-2.4–T-2.5.

## Symptom, evidence and root cause

Ubuntu conformance job [105312670403](https://github.com/hyper-light/slates/actions/runs/35253899553/job/105312670403)
failed hermeticity startup after 60 seconds. Its anchor repeatedly killed a daemon that reported
serving on two shards because it never saw a first heartbeat inside the recovery budget.

Every `HostClock::new()` captured a fresh `Instant` and returned elapsed time since construction.
The anchor compared its start and current readings to a heartbeat generated by another clock in
another process. A replacement process reset the heartbeat origin again. Status used a third
clock. An old anchor's `heartbeat >= started` test could therefore never succeed within its
startup budget, however regularly the daemon beat.

A regression drives a real supervised child twice through the shared segment, each using its own
HostClock. On macOS arm64, Rust 1.98.0:

```
cargo test -p slates-anchor --test anchor a_delayed_child_and_its_restart_beat_in_the_anchors_clock_domain -- --exact --nocapture
```

Before: fails in 0.12 s. Parent start 105022791 ns; child heartbeat 2792 ns; parent observation
112730208 ns. Second generation: start 113432125 ns, heartbeat 2458 ns. Both heartbeats appear
to precede their starts. This isolates the clock error without a tracer or scheduler pressure;
it does not rule out additional tracer startup costs in CI.

## Change

`slates-machine::clock::monotonic_ns` reads the OS clock with one boot/time-namespace origin.
`HostClock` holds no private epoch. Linux uses CLOCK_BOOTTIME; Darwin CLOCK_MONOTONIC; Windows
QueryInterruptTimePrecise, converting its 100 ns units. These readings include suspended time,
so a resumed process cannot extend a deadline by sleeping. They are neither Unix timestamps nor
comparable between different hosts/time namespaces. The RAM segment and every process attaching
it must share that domain; host reboot destroys the RAM state.

Sources: [Linux timekeeping](https://www.kernel.org/doc/html/latest/core-api/timekeeping.html),
[Apple clock implementation](https://github.com/apple-oss-distributions/Libc/blob/main/gen/clock_gettime.c),
[Windows interrupt time](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-queryinterrupttimeprecise).
Rustix's fixed ClockId API is infallible; the Windows void API needs one documented FFI output
pointer (machine unsafe budget 44 → 45). No wall-clock fallback or local-origin compatibility path.

The sibling sweep found daemon status freshness and locally logged lease deadlines using independent
HostClocks too. They now use the same domain without separate arithmetic. Anchor format 3 rejects
format 2 before recovery: mixing old and new clock conventions would misjudge both heartbeat
freshness and retained deadlines. Existing anchor sessions must be ended before changing between
these formats; rolling preservation across this format boundary is not supported. The hostile
handoff regression accepted version 2 before the bump (fails in 0.00 s), then refuses it typed.

## Validation

The seven original/enabled anchor histories, including two real child generations, pass in 0.16 s
before adding the format regression. Observed heartbeat ages: 31000 ns and 101000 ns.
`cargo test -p slates-vfs --lib --test base -- --test-threads=1`: 23 unit histories pass in 0.53 s,
20 base histories in 14.89 s. Strict clippy on machine, VFS, anchor, server and CLI passes in 9.84 s;
Windows x86_64 machine cross-clippy (pure-hash, no default features) passes in 4.71 s.
This is clock-domain and regression evidence; the privileged native hermeticity lane has not been rerun.

Final anchor suite: eight enabled integration histories pass in 0.16 s on macOS and 0.11 s
on Linux aarch64 (cached Rust 1.98 image, uid 1000, two CPU quota, no capabilities/network).
Linux heartbeat ages were 1159584 ns and 22417 ns. The real CLI lifecycle passes in 1.92 s:
`SLATES_TEST_CLI=1 cargo test -p slates-cli --test cli the_anchor_supervises_a_daemon_the_verbs_answer_and_the_daemon_leaves_with_the_anchor -- --exact --nocapture`.
`cargo xtask check` passes (2.19 s including invocation).
