# Slates product and codebase audit — 2026-09-29

## Verdict

Slates has a substantial design, unusually serious protocol tests, and meaningful implementation work across the whole product. It is not yet justified to treat the working tree as a safe, complete laptop-to-global filesystem service. The immediate blockers are permission enforcement at landing, unsafe memory lifetimes exposed through safe Rust APIs, hostile-input admission, and recovery that changes the meaning of an object. The fleet also has integration paths whose cost grows with the number of objects or members and delays consensus progress.

This audit records **63 findings** and a separate performance and scale improvement programme. The third pass adds 23 findings on RAM residency and containment, content authority/ownership/retention, handshake protection, congestion and scheduling, transfer resumption, and testing. A finding is not a request to layer in a fallback, add locks, add an external runtime, infer a merge, or put consensus on filesystem writes. Those would contradict the product. The fixes must strengthen the existing ownership, bounded-work, register, and grant mechanisms.

The most urgent finding is **AUD-29-01**: a grant issued for one target can authorize execution against another target. A valid issuer proof at grant creation does not fix missing binding checks at grant use. **AUD-29-08** exposes freed runtime state as a valid-looking static reference. These are product safety defects, not polish.

The requested pure in-memory isolation is also unproven: require_locked protects only one representation of content, replicated holders retain uncharged pageable buffers, and the trace oracle exempts regular-file logging. The third pass reproduced holder ownership failures, plaintext handshake certificate exposure and incorrect packet congestion accounting. A fast local core or a successful constrained-link benchmark does not close these boundaries.

## 1. Product understood before code was judged

The governing contract is [SLATES_DESIGN.md](../wip/SLATES_DESIGN.md), particularly §1, R1–R10, D-7–D-9, D-14–D-17, D-26–D-27, and §§4.2–4.16. [GAPS.md](../wip/GAPS.md) and [TBD_FIXES.md](../wip/TBD_FIXES.md) distinguish current implementation from historical gates.

Slates gives coding agents normal filesystem paths backed by isolated, copy-on-write RAM state. A volume may be scratch or a lazy overlay of a host directory. The host disk remains the source of truth for untouched base entries; private edits stay in RAM. Snapshots and clones share state. Ordinary programs must observe the specified filesystem semantics through the platform bridges.

A green volume accepts work through declared operations. It returns accept, identical, or precise conflict. It does not guess a text merge. A landing is a separate operation: present the precise changes, obtain a human grant, acquire authority for the target, preserve outsider changes, write only within the granted target, and report the achieved result and durability.

The fleet retains the same semantics. Shard ownership and bounded channels serve local work; fenced registers and placed content retain objects; a regional Raft council and cross-region root group agree configuration. Consensus is for membership, placement configuration, promotion, and home changes. Putting Raft on every file write would violate D-14 and would make local and wide-area latency requirements incompatible.

The promised scale is not “a small cluster eventually.” The design's §2 scale envelope names thousands of hosts, 32–192 cores per host, 256 GiB–2 TiB RAM, billion-file bases, and millions of loaded inodes. The user's global-scale requirement makes admission, scheduling, failure domains, retained metadata, and recovery costs first-class acceptance conditions.

| Product operation | Required observable guarantee | Implementation reviewed |
|---|---|---|
| Provision | Typed refusal or isolated volume; uncontended p99 below 50 µs | machine, mem, rt, ipc, client, server admission |
| Use a normal path | Correct namespace, bytes, links, attributes, handles, barriers, permissions | vfs, base, bridge-core and OS bridges |
| Snapshot / clone | Stable chosen version, bounded retention, no mutation through shared roots | vfs snapshots, image/export, server records |
| Merge | Declared operations only; exact verdict; replay and retry preserve the result | merge, merge_service, verbs, register holders |
| Place / take over | Acknowledged state survives the promised failures with its policy intact | archive, db, cluster, fleet, head, takeover |
| Land | Exact reviewed state, intended consumer, canonical target, outsider safety, honest durability | CLI/control authorization, server landing, land engine |
| Use an SDK or MCP | Async progress, bounded input and pending work, typed errors, no grant authority | client, Python, Node, MCP |
| Deploy globally | Bounded work independent of unrelated objects; consensus remains live under bulk load and failure | transport, fleet coordinator, council/root, retention, CI |

Slates is not a sandbox, persistent storage after total RAM loss, or a general multiwriter distributed POSIX filesystem. Those exclusions do not relax the guarantees above.

## 3. Severity and prioritized findings

**P0:** can break the human disk-write permission boundary.  
**P1:** memory unsoundness, wrong state or lost work, daemon termination, indefinite operation, or scale liveness failure.  
**P2:** important enforcement, efficiency, evidence, or product-truth weakness.

A priority is not a measured frequency. Boundary tests should be cheap even when the boundary is rare.

### AUD-29-01 — P0 — Landing execution does not enforce the grant's target, volume, or consumer

**Evidence: Source.** [server landing](../../crates/server/src/landing.rs), land_verb_unix around line 228 and issue_grant around 561; [grant table](../../crates/land/src/grant.rs), GrantRecord / Grants::check around 45 / 123; [manifest encoding](../../crates/land/src/manifest.rs), Manifest::encode around 170.

The durable grant records a volume, snapshot, target and principal. The runtime grant passed to the engine contains none of those bindings. Execution checks write rights on the requested volume, opens the requested target, and checks only the runtime grant's state, expiry and, for Once, manifest hash. The manifest hash covers relative entries and their witnesses, not target-root identity. Session grants do not even compare the manifest.

A caller with a usable grant id on that owner shard can retarget a create-only plan to another empty directory with the same manifest. A session grant can cover a different plan or writable volume on that shard. A target path replaced between presentation and execution is not bound to the reviewed directory identity either. The keyed proof authenticates grant issuance, but execution never enforces the fields it was meant to authorize.

**Required change:** carry a closed grant binding through use: stable target identity, volume, chosen state, intended consumer/session, scope, expiry and issuer authority. Compare it before any write-capable action and at resumption. Bind the granted target by identity, not just a string.

**Acceptance:** a granted create into A, then a retry into B, a replaced A, another volume, another consumer, and a widened session all refuse with zero host writes. Include same-content plans so manifest equality cannot hide the defect. §§4.13/4.15, R1/R10.

### AUD-29-02 — P1 — The landing snapshot argument is recorded but not used

**Evidence: Source.** [server landing](../../crates/server/src/landing.rs), lines 252–283; [landing engine](../../crates/land/src/engine.rs), land around 1530.

The server converts the requested snapshot into the database record, but passes the live mutable Volume to land. The engine plans and reads that volume's current overlay. It receives no selected snapshot. The recorded snapshot can therefore describe different bytes from those presented or written. There is no lookup validating the supplied snapshot in this path.

**Required change:** resolve and pin the requested immutable state before planning; make the engine's source explicit. Replanning, approval, execution and audit must refer to that same state, with defined advancement of subsequent live edits.

**Acceptance:** snapshot S, edit the live volume, land S and assert the old bytes were presented/written and later edits remain private. Unknown and foreign snapshots must refuse before writes. §4.15.

### AUD-29-03 — P1 — Target landing leases are shard-local, not target-global

**Evidence: Source.** [LandingState](../../crates/server/src/landing.rs), lines 63–77; [Leases](../../crates/land/src/grant.rs); [land](../../crates/land/src/engine.rs), lease take/release around 1565.

Each owner shard has its own Leases table. Two volumes on different shards can land concurrently into the same host target and each acquire its local lease. Database landing-lease records do not provide an enforced cross-shard target authority in this execution path. A path-string key alone is also insufficient against target aliases.

**Required change:** route a canonical target identity to one host-local lease owner, through the existing bounded ownership mechanism. Carry its fencing token through every write and resume. This is target landing serialization, not a new lock on ordinary filesystem writes.

**Acceptance:** two separately owned volumes and two aliases of one target produce one holder and one typed refusal. Include expiry, paused old holder, cancellation, and restart. §4.15 step 3.

### AUD-29-04 — P1 — A delete can remove an outsider's replacement

**Evidence: Source.** [engine delete](../../crates/land/src/engine.rs), lines 1107–1134.

A regular-file delete opens and fstats the file, closes its descriptor, then unlinks its name. An outsider may replace that name between the check and unlink. The new file is deleted without validation. If open_file returns NotFile, the code unlinks directly, without checking that the symlink or special entry is the witnessed object.

This is a separate issue from the replacement engine's exchange-and-verify logic. A passing replacement crash oracle does not prove deletion safety.

**Required change:** make removal a name transition that retains the displaced object, verify that exact object, and restore/refuse when it differs. Apply an equivalent identity discipline to symlinks, directory removal, recursive clear and rename.

**Acceptance:** inject outsider replacement at every host instruction around each removal. The outsider's bytes and name must survive; stale removal must conflict. §4.15, D-26.

### AUD-29-05 — P1 — Landing hides cleanup and durability failures, then can advance the source

**Evidence: Source.** [engine sync_all](../../crates/land/src/engine.rs), around 1345; land_under_lease around 1670–1740; [server finish](../../crates/server/src/landing.rs), around 427.

sweep errors become zero via unwrap_or(0). sync_all silently skips a touched directory when opening it fails without setting dirs_synced false. Some sync errors merely change the durability struct; the terminal state is computed principally from entry reports/crash classification. The server reply discards the engine's durability and degradation detail. Successfully written entries can be advanced out of the private overlay despite incomplete syncing.

**Required change:** classify every sweep/open/sync error. Preserve retryable divergence until the specified boundary is achieved, and return actual durability/degradation and concurrency facts in the public outcome. Distinguish an intentional supported durability level from a failed requested level.

**Acceptance:** inject directory-open failure, ENOSPC, sync failure and cleanup failure after writes; assert accurate public results and a subsequent resume that reaches the reference without losing private work. §4.15 steps 6–8.

### AUD-29-06 — P1 — Finishing a session landing marks its durable grant consumed

**Evidence: Source.** [server finish](../../crates/server/src/landing.rs), around 418; [Grants::consume](../../crates/land/src/grant.rs), around 155.

The engine consumes only Once grants. The server appends GrantStateChanged::Consumed for every supplied grant, including Session. Runtime and retained state disagree immediately. Grant listing and recovery can declare a live session grant spent; a restarted daemon cannot preserve the session contract.

**Required change:** publish the actual grant transition, with the intended consumer/session from AUD-29-01. Make the landing result and its terminal grant transition one correctly published operation where the recovery contract requires it.

**Acceptance:** issue a session grant, land twice, restart between landings, and verify continued validity only for its bound session/volume/target; Once is consumed exactly once. §§4.8/4.15.

### AUD-29-07 — P2 — Awaiting landing plans are neither bounded nor removed by successful use

**Evidence: Source.** [server landing](../../crates/server/src/landing.rs), present around 325, finish around 390, issue_grant around 561.

A presentation inserts an awaiting record at one landing id and advances next_landing. Execution allocates a fresh id; finish removes that fresh id, not the presentation's id. issue_grant leaves the awaiting record in place. Repeated plans retain target strings and metadata indefinitely, even after successful landings. The broader unpruned grant-record table is already an existing gap; this awaiting-map path adds a distinct leak.

**Required change:** a bounded, admitted plan lifecycle with an explicit presentation reference, expiry, consumption/revocation, and recovery behavior. Refuse before allocation when its derived capacity is spent.

**Acceptance:** many plan/grant/land cycles return the retained-plan count to the defined floor; abandoned plans expire, and capacity refusal changes no state. R3, ban 8.

### AUD-29-08 — P1 — Safe runtime APIs return references to state that is freed

**Evidence: Source; unsafe witness intentionally not executed.** [LocalRuntime](../../crates/rt/src/runtime.rs), Drop around 437 and context around 502; [SimRuntime::context](../../crates/rt/src/sim.rs), around 1083; [ShardContext::keep](../../crates/rt/src/shard.rs), around 402; [registry::reclaim_context](../../crates/rt/src/registry.rs), around 398.

context returns a static reference, but Drop reconstructs and drops the backing Box. Safe Rust can keep that reference after the runtime dies and call counters or other methods on freed memory. keep likewise returns a static reference to an object owned by the reclaimable context. A kept Send/Sync value can escape to another thread even though the context itself cannot. Public safe reclaim_context additionally accepts a numeric shard id without proving owning-thread or stopped-loop authority.

**Required change:** owner-bound borrows or generational handles whose use validates lifetime. Make reclamation private to an ownership proof. Do not repair this by leaking contexts forever or introducing Arc.

**Acceptance:** compile-time lifetime tests reject escaping references; Miri runs owner teardown with held handles, stale wakers and kept values. Audit every API returning static state from a reclaimable owner. §§4.2/4.3, R2.

### AUD-29-09 — P1 — Shared mapping APIs do not enforce the atomic/plain-byte aliasing rule

**Evidence: Source; Miri proof still required.** [shared mappings](../../crates/mem/src/shared.rs), bytes / atomic_u64 around 100–120 and word_view around 255.

The safe API can return a plain shared byte slice and an atomic view over the same bytes. A caller can retain the former while storing through the latter. word_view's SAFETY comment requires all other accesses to those bytes to be atomic, but bytes exposes unrestricted non-atomic access. Cross-process mappings make this discipline more important, not less.

**Required change:** establish interior mutability at the storage boundary and typed, disjoint ownership of byte ranges versus atomic words. Safe callers must not be able to create conflicting access. Check SparseObject and every IPC/anchor mapping user as siblings.

**Acceptance:** memory-model tests exercise retained byte views, atomic mutation, mixed widths, concurrent access and teardown. A comment is not an enforced invariant. §§4.2/4.7.

### AUD-29-10 — P1 — Buddy free accepts a forged block and corrupts its accounting

**Evidence: Run.** [buddy allocator](../../crates/mem/src/buddy.rs), free around 134; [arena](../../crates/mem/src/arena.rs), free.

Allocate 4,096 bytes from an 8,192-byte region, then free offset 1 / length 4,095. free accepts it, reports 8,191 free bytes, and coalesces an 8,192-byte block. The next 8,192-byte allocation panics in the debug probe. Floor division and rounded order are not exact block validation.

**Required change:** validate alignment, exact allocated length/order, range and allocation incarnation before changing free lists or totals. Prefer unforgeable owner handles; a publicly constructible extent also needs stale-reuse protection.

**Acceptance:** forged length/offset, interior free, cross-arena free, duplicate free and stale extent after reuse all refuse with unchanged accounting and subsequent valid allocation behavior. §4.2.

### AUD-29-11 — P1 — Generation wrap revives stale handles; packed wakers have a smaller alias boundary

**Evidence: Run plus Source.** [slab](../../crates/mem/src/slab.rs), generation updates around 77 / 274 / 296; [handle encoding](../../crates/mem/src/handle.rs), pack around 98 and matches around 139; [runtime wake validation](../../crates/rt/src/shard.rs), handle_wake around 1263.

With generation_base = u32::MAX, one remove/reinsert yields generation zero; an ancient generation-zero handle resolves to the new object. The runtime encoding stores and compares only 24 generation bits, so its alias boundary is 2^24 reuses of one slot, before the full 32-bit wrap. The comment describing the event as counted does not make masked equality detect it.

**Required change:** retire slots before exhausting the generation space of every representation and return the design's typed GenerationExhausted refusal. Preserve exhaustion across runtime/shard reuse. Never wrap or mask away the evidence of a stale handle.

**Acceptance:** initialize directly near both boundaries; exercise stale slab handles, wakers, cancelled tasks and recycled shard ids without running millions of iterations. §4.2, §4.3.

### AUD-29-12 — P1 — Runtime startup and drop can orphan worker threads

**Evidence: Source.** [Runtime::start / shutdown](../../crates/rt/src/runtime.rs), around 291–418.

Runtime owns JoinHandles but has no Drop that cancels and joins its workers. Dropping it detaches workers. A later thread-spawn failure drops already-created handles through the question-mark return. A worker whose ShardContext::build fails returns default counters; start can still return success with a nonfunctional shard. shutdown also converts thread panic into default counters.

**Required change:** transactional startup with worker readiness acknowledgements and rollback; explicit owned terminal state for all workers; typed failure reporting. Destruction must not silently detach active runtimes.

**Acceptance:** fail each preparation/spawn/context-build step, drop without explicit shutdown, and prove no live worker or registry slot remains. A failed shard must not be advertised as started. §4.3, ban 9.

### AUD-29-13 — P1 — Archive parsing admits decompression and reconstruction before memory admission

**Evidence: Source.** [archive read_chunk / decode_payload](../../crates/archive/src/archive.rs), around 481–532; [manifest reader](../../crates/archive/src/manifest.rs), around 289; [takeover restore](../../crates/server/src/verbs.rs), around 5225–5237.

The compressed payload's raw_len is used as the decompressor's output capacity without a per-chunk or cumulative admitted bound. Raw chunks do not require declared raw_len to equal their content length. Recursive manifest parsing has no depth bound. restore expands holes into Vecs and reconstructs the whole volume before the server reserves the volume's content budget.

A valid outer checksum does not make attacker-chosen sizes trustworthy; the sender can compute its own checksum. A small encoded object can demand a much larger heap or stack. An enrolled peer is authenticated, not trusted.

**Required change:** admission-aware decoding with caps on raw chunk size, total reconstructed content, entries, extents, names, depth and transient bytes; checked conversion and fallible allocation. Stream admitted output into the owning arena and use an iterative bounded manifest walk.

**Acceptance:** maximal raw_len, huge holes, repeated compressed references, deep nesting and metadata amplification refuse within a measured memory/CPU bound before allocation. §§4.2/4.9/4.11.

### AUD-29-14 — P1 — Archive restore ignores each extent's file offset

**Evidence: Run with raw-chunk fixture; Source.** [restore_file](../../crates/archive/src/restore.rs), around 47.

The implementation appends every extent and never reads extent.offset. A one-byte extent at file offset eight restores as [65], not eight zeros followed by A. Out-of-order and overlapping extents have no validation. The returned bytes may disagree with both the manifest metadata size and the hashed extent description.

**Required change:** either validate the canonical contiguous extent contract and refuse every gap/overlap/misordering, or honor checked file offsets and explicit holes under the design's sparse-file rule. Check final size against metadata.

**Acceptance:** sparse, out-of-order, overlapping, truncated and overflowing extent lists cannot silently restore different bytes. Verify through archive decode and the actual successor materialization path. §4.11, AC-7.3.

### AUD-29-15 — P1 — The manifest decoder accepts noncanonical and ambiguous trees

**Evidence: Run for trailing bytes and invalid component; Source for duplicate/order behavior.** [Node::decode / read](../../crates/archive/src/manifest.rs), around 282–321; [restore walk](../../crates/archive/src/restore.rs), around 71.

decode does not check exhaustion of input. Directory names are only checked for UTF-8, not valid single components; "../outside" is accepted. Sortedness and uniqueness are not enforced. restore builds string paths and inserts into maps, so duplicate paths can overwrite earlier nodes or metadata. Merkle verification can authenticate an ambiguous tree without resolving these semantic defects.

This audit does not claim a demonstrated host-path escape: downstream name validation may refuse it. Acceptance by the supposedly canonical format boundary is already wrong.

**Required change:** exact decoding, validated components, ordered unique entries, unambiguous inode/type/metadata rules, and canonical extents before publishing an Archive.

**Acceptance:** trailing bytes, dot/dot-dot, separators, NUL, duplicate names, unsorted names and path collisions refuse typed. Valid encodings retain deterministic identities. §§4.9/4.11.

### AUD-29-16 — P1 — Rename onto a base directory does not use the base-aware emptiness check

**Evidence: Source.** [Volume::rename](../../crates/vfs/src/volume.rs), around 1360–1393; [Overlay::rename](../../crates/vfs/src/base.rs), around 1427; compare Overlay::rmdir around 1390 and empty_for_rmdir around 659.

A materialized base directory starts with a merged node and an unloaded child listing. rmdir loads that listing and checks both overlay entries and base whiteouts. rename instead tests DirNode::is_empty. It can treat a directory with untouched disk children as empty and replace it. Overlay::rename does not load the target directory's child listing before delegating.

The same functions swallow target lookup errors with .ok() / let _ instead of distinguishing NotFound from stale, host or admission failure. That obscures the guarantee that a refused rename changes nothing.

**Required change:** one base-aware target validation path for rename and rmdir, with explicit handling of NotFound only. Secure all mutation resources before removing either source or target.

**Acceptance:** rename a directory over a nonempty lazy base directory before reading its children; expect NotEmpty and both trees unchanged. Repeat after listing, watcher invalidation, CoW and injected allocation/host refusal. §4.5, POSIX equivalence.

### AUD-29-17 — P1 — Takeover reconstructs a weaker volume policy and drops access state

**Evidence: Source; existing broader catalog-transfer gap.** [HeadValue](../../crates/server/src/head.rs), around 27; [materialize_taken_over](../../crates/server/src/verbs.rs), around 5317.

The placed head carries content identity, holders, name, size, name policy and owner. It does not carry require_locked or the access list. Reconstruction assigns require_locked = false, Role::Plain, Scratch base, no lease, and an empty access list. ContentHold owns unbounded BTreeMaps of heap-owned chunks and manifests. Its refusal taxonomy has no byte/headroom admission refusal. An enrolled peer can put successive valid archives without charging the VFS arena or the host's outstanding entitlements. Valid shipped chunks need not be referenced by the manifest. Duplicate-manifest replacement does not release the prior hold. The only server caller of forget_manifest is the explicit test fault injection; there is no production release tied to snapshot destruction, completed replacement, object destruction or retired placement.

Thus a bounded VFS does not bound its replicated-content holder. Continuous sealing and healing retain historical manifests indefinitely; unique bytes can consume RAM promised to admitted volumes. There is no permissible disk spill to absorb this.

**Required change:** reserve chunk, manifest, reference and transient costs atomically before verification/storage; restrict shipped content to the authorized closure; reclaim only after all authoritative snapshot/placement/read references release. A live placed reference must never be evicted to make room.

**Acceptance:** churn seals, retries, healing, destroys and cohort changes while an unrelated volume spends its promised allowance. Hold usage must reach a derived bound, refuse typed there, and return to the surviving-reference baseline after retirement. §4.2, §4.10, R1/R4.

### AUD-29-44 — P1 — Holder reference counts do not represent manifest ownership

**Evidence: Run; 2026-09-29.** [ContentHold::hold / forget_manifest](../../crates/cluster/src/content.rs), around 510–542; [ContentStore::insert / release](../../crates/archive/src/store.rs). Reproduction: §7.4.

Three bounded witnesses:

- Put the same manifest twice, forget it once: 0 manifests, **1 retained chunk**.
- Hold A, hold B referencing A's already-held chunk without shipping it, forget A: B still declares itself held, but archive_of(B) returns None and **0 chunks** remain.
- Ship one valid unreferenced chunk, then forget the manifest: **1 orphaned chunk** remains.

Insertion counts supplied chunks; removal counts referenced chunks. These are different sets. Retry identity and dedup across manifests therefore break both reclamation and the meaning of “held whole.” Production currently lacks retirement (AUD-29-43); the premature eviction witness uses the public loss/release seam, not a claimed live production GC call.

**Required change:** acquire one reference for every newly installed manifest's distinct referenced chunk, regardless of whether bytes arrived in this put. Repeated puts must be idempotent. Reject or explicitly account for unreferenced payloads; release exactly the acquired references.

**Acceptance:** a serial manifest-to-chunk ownership oracle over put/retry/partial-put/release/failure histories; every held manifest remains reconstructible, unrelated bytes never remain after their last reference, and failed operations change no ownership. AC-7.3/AC-8.12.

### AUD-29-45 — P1 — Content hashes authorize existence queries and fetches on the fleet plane

**Evidence: Source; inspected 2026-09-29.** [ContentMessage / ContentHold::serve](../../crates/cluster/src/content.rs), Fetch around 142 and serve around 559; [authenticated dispatch](../../crates/server/src/fleet.rs), serve_peer_records.

Mutual TLS and enrollment identify a host. They do not authorize each content reference. The content handler receives local holder identity and request bytes, but no requesting principal, delegated consumer, object authority or sharing scope. Offer answers missing_of against the holder's entire chunk store. Fetch names only a manifest hash and returns its whole archive. Put carries an object and sequence but does not validate them against the peer's current authority before allocating or acknowledging.

An enrolled host can query whether guessed private chunks exist and fetch a known private manifest without proving permission to that object. This is an authenticated-host boundary defect; this audit has not demonstrated an unauthenticated SDK client reaching that wire path.

**Required change:** bind every offer/put/fetch to an authorized object reference, requesting consumer scope and current placement/fence before existence lookup or allocation. Physical dedup may share bytes only within the declared sharing policy; hashes remain identities, not bearer rights.

**Acceptance:** two mutually isolated consumers sharing one holder cannot reveal each other's bytes or existence through offers, cached fetches, errors or measurable timing. Repeat after revocation, takeover and reconnect. §4.13 “Content identity and sharing”; the already-owed fleet delegation is a blocker.

### AUD-29-46 — P1 — Flow-control consumption becomes unbounded whole-message heap retention

**Evidence: Source; inspected 2026-09-29.** [Endpoint::drain / begin](../../crates/transport/src/endpoint.rs), around 1148 and 1350; [StreamSender::write](../../crates/transport/src/stream.rs); [Connection::read_stream](../../crates/transport/src/connection.rs).

Endpoint drains contiguous stream bytes, advances receive credit, then appends those bytes to arriving or reply Vec buffers. It enforces no cumulative request/reply byte cap or charged destination reservation. A peer that never sends FIN can keep sending within each newly returned window while one accumulated message grows beyond receive_ceiling. Stream concurrency bounds the number of messages, not their retained bytes. This is distinct from AUD-29-35's aggregate reassembler-credit defect.

On send, opening/replying copies the entire source into StreamSender::buffered; frames add copies retained for retransmission. Small wire credit does not make this source storage bounded by credit. Fetch and put layer whole-archive buffers on it.

**Required change:** parse the bounded authenticated envelope before growing a body; receive into admitted object/range storage, returning credit only when destination capacity is owned. Unknown lengths need bounded, expiring RAM operation handles. Source and retransmission views must have admitted ownership.

**Acceptance:** a never-FIN sender, oversized reply, concurrent bulk sources and stalled destination all meet typed caps with control still live and charges returned on cancellation. Measure peak bytes, not only EndpointCensus's object counts. §4.2, §4.9, AC-7.7/T-7.8.

### AUD-29-47 — P1 — The handshake sends TLS-protected-level messages as plaintext fragments

**Evidence: Run + Source; 2026-09-29.** [Endpoint::drain_handshake / send_flight_at](../../crates/transport/src/endpoint.rs), around 937–990; [flight::fragment](../../crates/transport/src/flight.rs). Reproduction: §7.4.

drain_handshake concatenates output across encryption-level boundaries, ignores Handshake key changes, and retains only OneRtt keys. send_flight_at sends that concatenation through the raw fragment codec. A passive observer reconstructed the generated server certificate's DER bytes directly from the fragment payload. The probe saw one Handshake key change and one OneRtt change; no socket or private-key output was involved.

rustls::quic supplies unencrypted handshake bytes for its caller to protect. QUIC does not supply TLS record encryption underneath them; encryption-level separation and protection belong to the transport. [RFC 9001 §§4.1.3–4.1.4](https://www.rfc-editor.org/rfc/rfc9001.html#section-4.1.3).

This exposes handshake metadata and certificate identities. It does not demonstrate disclosure of private keys, acceptance of a forged peer, or plaintext established file-transfer payloads.

**Required change:** retain each encryption level's keys, offset and packet space; protect and retransmit its bytes at that level rather than flattening the handshake. The owned dialect must preserve its stated security contract.

**Acceptance:** observe a full mutual handshake, including fragmented certificate chains and retries; protected-level certificate/handshake bytes are absent from unauthenticated wire plaintext, tampering refuses, and lost/reordered level transitions complete. §4.10a, D-15.

### AUD-29-48 — P1 — Long-lived sessions never update keys or enforce AEAD usage limits

**Evidence: Source; inspected 2026-09-29.** [Endpoint keys and packet protection](../../crates/transport/src/endpoint.rs), drain_handshake / fold_or_discard / protect_packet. Pinned rustls 0.23.44 exposes PacketKey::confidentiality_limit and integrity_limit in src/quic.rs.

OneRtt's next_secrets are discarded; the key-phase bit stays zero; the initial keys protect the session for its lifetime. There is no encrypted-packet usage counter or failed-authentication budget. Invalid packets are discarded indefinitely. This boundary occurs independently of packet-number exhaustion in AUD-29-27.

QUIC requires per-key encrypted-packet accounting and connection-wide failed-authentication accounting; keys must update or the connection must close before the applicable limit is exceeded. AES-GCM's specified confidentiality limit is 2^23 packets, far below the packet-number ceiling. [RFC 9001 §6.6](https://www.rfc-editor.org/rfc/rfc9001.html#section-6.6).

**Required change:** own the next key material, update/confirmation/reordering lifecycle and provider-derived budgets; return a typed terminal outcome if safe continuation is impossible. Review the control-plane Sealer's per-key bounds separately; nonce uniqueness alone is insufficient evidence.

**Acceptance:** use a test provider with a deliberately small usage allowance; cross it through data, ACKs, probes and retries. Require key update or closure, no nonce reuse, bounded old-key retention and correct reordering. No billions-of-packets test is needed.

### AUD-29-49 — P1 — Pre-authentication flights have no address-validation amplification budget

**Evidence: Source; inspected 2026-09-29.** [Demux::route / Inner::open](../../crates/transport/src/demux.rs), around 468 and 558; [raw flight send](../../crates/transport/src/endpoint.rs), send_flight_at / receive_flight.

Any previously unseen source carrying a non-short-header datagram can allocate a pending TLS endpoint. Once a ClientHello is processed, the server sends its full fragmented flight; there is no per-unvalidated-address received/sent byte account or address-validation token. Flight and pending-session bounds cap individual memory but do not bound reflected traffic or pre-authentication cryptographic CPU. TLS peer authentication happens later.

QUIC bounds bytes sent to an unvalidated address to three times bytes received, including retries. [RFC 9000 §8.1](https://www.rfc-editor.org/rfc/rfc9000.html#section-8.1). The private dialect still needs an explicit reflection-resistance contract; this is not an interoperability claim.

**Required change:** bound unauthenticated work and output before state-heavy processing, validate address ownership, and preserve established-service reservations through churn. Repeated raw traffic to an established endpoint must not trigger unrestricted final-flight/confirmation traffic either.

**Acceptance:** simulated spoofed sources, large chains, malformed fragments and repeated old flights cannot exceed their output/work allowance or starve an established control exchange. No reflected live traffic was generated in this audit.

### AUD-29-50 — P1 — Congestion and pacing account payload bytes instead of transmitted packet bytes

**Evidence: Run + Source; 2026-09-29.** [tracked_bytes / SentTracker](../../crates/transport/src/conn.rs), around 217/277; [Connection::record_sent / poll_probe](../../crates/transport/src/connection.rs), around 792/416. Reproduction: §7.4.

The congestion window, ACK growth input, in-flight count in bytes and pacer token spend use Stream payload length. Frame headers, packet/header-protection padding, AEAD/header overhead and non-Stream reliable frames spend no corresponding bytes. PMTU Ping probes are recorded with a size but bypass the window and pacing accounting.

At one clock instant, the pure connection emitted **1,000 one-byte packets**, counted **1,000 bytes in flight** against a **12,000-byte window**, and sized them at **52,000 bytes** using its own upper-bound overhead. Accounting for the actual packet-number lengths gives **49,873 protected packet bytes**; these are calculated sizes, not a live-wire capture.

QUIC's in-flight byte definition includes the protected packet size, including headers and padding, while excluding IP/UDP overhead. [RFC 9002 Appendix B.2](https://www.rfc-editor.org/rfc/rfc9002.html#appendix-B.2).

**Required change:** distinguish application progress/flow credit from packet congestion bytes. Spend actual protected sizes; account ordinary reliable control and probes correctly, preserving only legitimate ACK/PTO exceptions.

**Acceptance:** tiny-stream, empty-FIN, reset, padded-probe and full-packet histories obey congestion/pacer bounds against a serial packet ledger. Repeat the existing controller/scheduler measurements after correcting the accounting.

### AUD-29-51 — P2 — A small urgent frame is refused while ample space for that frame remains

**Evidence: Run; 2026-09-29.** [Connection::take_fresh](../../crates/transport/src/connection.rs), around 748–758. Reproduction: §7.4.

take_fresh checks window_room against the maximum prospective payload cap before selecting a frame. It does not use the selected frame's actual size or reduce the cap to available window space. With **11,000 payload bytes in flight**, a **12,000-byte window** and **1,000 bytes spare**, a new **one-byte control request** produced no control frame at a 1,200-byte packet budget. The pacer had time to refill. ACK arrival may eventually free enough for a maximum-size frame, but the delay is avoidable.

The same prospective-budget choice appears in pacing_hold: a short urgent packet can wait for tokens sufficient for a full budget. That pacing consequence is a source-backed experiment to measure, not a separate reproduced result.

**Required change:** select/reserve the actual next packet/frame cost within available wire-window and pacer space without destructively advancing an unsent stream.

**Acceptance:** urgent frames fitting the remaining window/tokens leave immediately; larger frames wait or split legally. Test with piggybacked ACKs, credit changes and retransmissions. §4.10a, R4.

### AUD-29-52 — P1 — Lost bulk traffic overrides the advertised control priority

**Evidence: Source; inspected 2026-09-29.** [poll_transmit / take_retransmissions / next_fresh_frame](../../crates/transport/src/connection.rs), around 549/646/931.

All retransmissions drain from one FIFO before any fresh stream. The front frame's class is not compared with a new control stream's class. A lost bulk window therefore consumes newly available window/pacer space before a newly queued membership/configuration/record request. A front bulk frame that cannot fit can stop selection altogether. Existing strict priority applies only to fresh data. Shared congestion and connection credit also carry no class reservation.

This is a congestion-dependent ordering defect, not a claim that control can jump bytes already serialized onto the link. The existing clean-path same-session priority test does not establish behavior behind a bulk retransmission backlog.

**Required change:** schedule eligible retransmissions and fresh frames by authenticated purpose under one congestion budget, with measured starvation/fairness bounds. Preserve retransmission range identity and liveness; give control headroom before bulk consumes shared admission and credit.

**Acceptance:** create a known bulk-loss backlog, inject control/metadata, and measure their latency versus the unavoidable serialization/queue bound while bulk still progresses. Include reverse-path congestion and exhausted credit. §4.9 classes, §4.10a.

### AUD-29-53 — P1 — An awaited application handler stops the session's transport progress

**Evidence: Source; inspected 2026-09-29.** [Endpoint::serve_once_async](../../crates/transport/src/endpoint.rs), around 1272; [serve_peer_records](../../crates/server/src/fleet.rs), around 2517; [ContentHold::serve](../../crates/cluster/src/content.rs).

serve_once_async awaits its one handler without driving Endpoint. During a forwarded verb's cross-shard wait, existing replies, receive draining, paced sends, loss recovery and later control requests on that session have no owner driving them. Its comment says already-sent replies keep flowing, but this function does not poll that work during the await. The fleet serves requests serially through this API.

A content handler also verifies, decompresses, hashes and encodes whole archives synchronously in a control-shard state borrow. Separate QUIC streams cannot preempt that work. This is additional to AUD-29-28's outgoing coordinator barrier.

**Required change:** keep a single owning peer driver alive while bounded operation handles await results; return results to it by move. Slice admitted parser/codec/hash/restore work and validate operation purpose before spending bulk CPU.

**Acceptance:** hold an actual forwarded handler pending; lose its preceding reply; concurrently send a Raft request and bulk data. Both transport recovery and control must progress before the handler resolves. Repeat with an expensive valid content request and record the maximum shard step. R6, §4.3/§4.9.

### AUD-29-54 — P2 — The peer can choose its own receive-service priority

**Evidence: Source; inspected 2026-09-29.** [stream-id classes](../../crates/transport/src/streams.rs), compose / priority; [Endpoint::most_urgent_ready](../../crates/transport/src/endpoint.rs), around 1380; [fleet dispatcher](../../crates/server/src/fleet.rs).

Priority bits are sender-selected. The receiver chooses ready work from those bits, while next_request supplies the handler only the kind and bytes. There is no binding between an authorized request kind, its permitted class, size/CPU allowance and the receiving operation. An enrolled peer can label a content request Control and obtain that receive ordering; a genuine control request can likewise carry a bulk-sized malformed body into parsing.

Transport peer identity does not establish application-purpose priority. The unused class value becoming Bulk also means malformed purpose is not refused as such.

**Required change:** derive permitted purpose/class from the authenticated operation and reject inconsistent ids/envelopes before privileged queuing or allocation. Cover receive, CPU, destination, retry and send admission, not only fresh packet selection.

**Acceptance:** relabel content as control, send oversized control bodies and flood one enrolled peer; valid membership/record work remains live, refusals are typed/counted, and bulk cannot consume the control reserve. §4.9 “Classes”.

### AUD-29-55 — P2 — Transfer resumption preserves completed archives, not verified partial progress

**Evidence: Source / Existing gap; inspected 2026-09-29.** [content exchanges](../../crates/cluster/src/content.rs), puts_for / serve / fetch_content; [whole-message endpoint](../../crates/transport/src/endpoint.rs), drain.

Missing-set resumption exists between whole successful holds. Put sends one partial archive as one whole stream body; the receiver stores chunks only after FIN, complete archive decoding and verification. A disconnect after most bytes of a large put discards all that request's accumulated progress. The next offer still reports those chunks missing. Fetch always returns the whole archive rather than authorized missing ranges/chunks. No named bounded operation retains independently verified partial chunks or range progress across redial.

QUIC retransmission can recover loss within a surviving session. That is different from application transfer resumption after cancellation, peer restart or session replacement.

**Required change:** realize §4.9's admitted named-object/missing-set and verified-range operation with bounded RAM retention, cancellation ownership and expiry. A received range is not a placement ACK; only a complete authorized closure qualifies.

**Acceptance:** cut each transfer after every chunk/range boundary and around FIN/ACK; resume sends exactly the still-missing verified work, never counts incomplete content placed, and returns all abandoned storage. AC-7.7/T-7.8, T-7.5.

### AUD-29-56 — P1 — A placed archive silently loses extended attributes and observable times

**Evidence: Source; inspected 2026-09-29.** [export node_meta](../../crates/vfs/src/export.rs), around 557–584; [NodeMeta](../../crates/archive/src/manifest.rs); [restore_owner_and_times](../../crates/server/src/verbs.rs), around 5528.

The VFS has extended attributes and signed atime/mtime/ctime/btime. Export carries no attribute values and writes xattr_flags = 0. The archive metadata has no atime or btime; negative mtime/ctime clamp to zero. Takeover sets atime to the archived mtime. The resulting content can be verified and marked placed while a successor serves observably different metadata. Two snapshots differing only in omitted attributes can have the same exported identity.

Hard-link restoration is implemented and checked by inode groups; this finding does not claim that every file kind or ownership field is lost. The gap ledger's archive history describes an xattr-present flag, not preservation of attribute values. Acceptance must exercise the actual placed metadata.

**Required change:** carry and identity-bind every promised metadata field and attribute value; preserve signed ranges or refuse unsupported values before claiming complete placement. Recovery must preserve scope/policy as well as bytes (AUD-29-17).

**Acceptance:** mount → metadata/xattr edits → snapshot/place → owner loss → mount successor, comparing values, read/permission behavior, hard-link relationships and times. Include attribute-only changes and root attributes. §4.5/§4.10/§4.11, R8.

### AUD-29-57 — P2 — Sparse files become logical-size work and dense restored storage

**Evidence: Source; inspected 2026-09-29.** [SnapshotArchiver::step_file](../../crates/vfs/src/export.rs), around 384; [restore_file](../../crates/archive/src/restore.rs); [populate_restored](../../crates/server/src/verbs.rs), around 5461.

Export walks every byte through logical EOF, including holes, hashes zero buffers and emits ordinary chunk extents rather than preserving the VFS's sparse ranges. Dedup may retain one shared zero chunk, but walking work and manifest extent count still grow with logical size. Eager restore expands all extents into a whole-file Vec, and takeover writes that Vec through Volume::write, materializing zeros.

A volume with a very large sparse file and little admitted physical content can therefore require logical-size transient memory or fail takeover under a quota sufficient for its original sparse state. Restored SEEK_DATA/SEEK_HOLE behavior also changes. AUD-29-14 separately covers wrong extent offsets.

**Required change:** export the exact sparse extent map and logical length; restore/attach through admitted range references and holes, preserving physical allocation semantics. Avoid logical-size buffers and repeated hard-link content walks.

**Acceptance:** truncate large files, write sparse islands, punch holes, snapshot/place/take over; compare bytes, logical length, hole seeks and physical charge against the serial oracle. Seal/transfer work must follow referenced data plus metadata, with non-vacuity counters for hole preservation. §4.5/§4.11.

### AUD-29-58 — P2 — Content offers impose an unnecessary slowest-peer barrier before puts

**Evidence: Source; inspected 2026-09-29.** [put_content / gather / puts_for](../../crates/cluster/src/content.rs), around 712–839.

The offer round gathers all requested peers until every task ends or its stall policy expires. Only then are puts dispatched to peers whose missing sets already arrived. In hedged rounds, or whenever more offers are outstanding than the remaining quorum needs, one slow offer delays a fast holder that could complete placement now. The recorded put latency starts after this barrier, so the hedge's p95 excludes that delay.

The initial smallest candidate set may need every reply; the needless barrier matters when extra candidates or acknowledgements already exist. This is a protocol-phase delay distinct from the fleet coordinator's all-shard wait in AUD-29-28.

**Required change:** progress each authorized holder's offer → missing put independently and gather complete bound ACKs as they arrive. Retain explicit ownership of late sessions/results; do not abandon required closure verification.

**Acceptance:** one remaining ACK needed, two offers outstanding, one answer stalled: the fast holder receives its put and completes before the slow offer times out. Report whole placement latency, phase latency, useful/hedged bytes and recovered late sessions. §4.8/§4.10, R4.

### AUD-29-59 — P1 — A remote content ACK has no anchor-owned publication

**Evidence: Source; inspected 2026-09-29.** [holder ACK](../../crates/cluster/src/content.rs), ContentHold::serve; [server dispatch](../../crates/server/src/fleet.rs), around 2636; [state construction](../../crates/server/src/daemon.rs), held_content around 2377; [state contract](../../crates/server/src/state.rs), around 521.

A holder ACKs after inserting an archive into its process-local ContentHold. The handler does not publish those chunks/manifests into anchor-owned storage. Every reconstructed ShardState starts held_content as new(). Local owned-volume images and retained Raft/register records use separate recovery machinery; none restores this remote-content store.

Consequently a warm daemon restart can discard a replica that placement counted even though its anchor retained RAM. Healing can later resend it while an owner is reachable; eventual healing does not establish retention before ACK or durability through the interval before repair. The current warm-fleet regression checks root/regional quorums, not this content promise.

**Required change:** publish the complete authorized holder closure and its ownership record into admitted protected anchor RAM before ACK, and recover it before serving/counting that holder. Whole-anchor loss remains the distinct RAM-fault case; no disk persistence is permissible.

**Acceptance:** retain anchors, restart holder daemons at each publication/ACK instruction, suppress repair, then lose the original owner within the promised fault bound. Surviving holders must serve the acknowledged bytes and metadata, or never have issued that ACK. §4.8 persistence-before-reply, §4.10 placement closure.

### AUD-29-60 — P2 — Connection-id routing does not provide validated path migration

**Evidence: Source; inspected 2026-09-29.** [Endpoint::send / receive_and_ingest](../../crates/transport/src/endpoint.rs), around 529/1053; [Demux::route / deliver](../../crates/transport/src/demux.rs).

Established packets route by connection id and authenticate under the session keys, but incoming source addresses are discarded. Every response still sends to the original self.peer; no authenticated path-validation exchange adopts a new address or resets path congestion/MTU state. NAT rebinding or Wi-Fi/cellular handoff can therefore deliver valid incoming packets while responses continue toward the old address. Re-dial is session recovery, not migration, and currently loses partial transfer work (AUD-29-55).

**Required change:** specify and implement bounded validated address change in the owned dialect, preserving principal/completion identity and per-key packet-number discipline. Re-measure path state on a validated change; an unauthenticated packet or claimed address cannot redirect responses.

**Acceptance:** change only the source mapping during active bidirectional traffic, lose/reorder validation messages, and replay packets from the old path. Continuation must obey its authority, anti-amplification and RAM limits, or terminate typed with resumable work. §4.10a; [RFC 9000 §§8.2, 9](https://www.rfc-editor.org/rfc/rfc9000.html#section-9) supplies the security boundary, not proof this dialect implements it.

### AUD-29-61 — P2 — Local UDP send pressure becomes a session error after send state advances

**Evidence: Source; inspected 2026-09-29.** [UdpSocket::send_to](../../crates/rt/src/udp.rs), around 129; [Unix/Windows send seam](../../crates/rt/src/netsys.rs), around 166/445; [Endpoint::flush](../../crates/transport/src/endpoint.rs), around 999.

Nonblocking send errors, including local would-block/buffer pressure, become RtError and propagate from Endpoint::send. There is no write-readiness wait or bounded owned pending-datagram state. poll_transmit has already advanced stream offsets, charged pacing and recorded the packet as sent before the OS accepts it. A serve error ends the peer loop; other callers retain a session whose recorded send time predates acceptance. Either outcome adds avoidable recovery churn on congested hosts.

The simulation send path accepts every non-oversized datagram; it does not reproduce kernel send saturation. Network drop/queue scenarios therefore do not test this local pressure boundary.

**Required change:** represent prepare/accepted-send/pending-send explicitly under the existing executor's readiness/completion seam, retaining bounded ownership and assigning accurate loss/RTT state when accepted. Do not busy-retry or silently reset live work.

**Acceptance:** inject would-block, local buffer exhaustion and cancellation before/after OS acceptance on each platform seam. No false completion, packet-number reuse, lost frame, orphaned buffer or peer retirement caused solely by temporary local pressure. §4.3/§4.10a.

### AUD-29-62 — P1 — Windows base access lacks descriptor-relative containment

**Evidence: Source / Existing gap; inspected 2026-09-29.** [Windows OsHost](../../crates/base/src/windows.rs), open_root / list / open_dir / open_file around 145–249.

Directory handles are PathBuf entries, not retained OS directory handles. Each access re-resolves the path. open_file checks symlink_metadata then calls ordinary File::open; the check and actual open can name different objects, and an intermediate directory can become a junction/reparse point. Attribute fingerprint opens use OPEN_REPARSE_POINT for the final component, but do not turn the subsequent file/list operation into a contained relative open. The module openly records this incomplete platform seam.

Later fingerprint validation may refuse some replacements; it does not prove that no outside object was opened, nor bind an initially unloaded listing to a retained base-root handle. No Windows leak was executed on this Darwin host.

**Required change:** replace the path-based access with the design's handle-relative contained read seam and reparse checks on the actual opened objects. Until that contract is available, refuse the operation; do not leave a permissive alternate implementation active.

**Acceptance:** swap root/intermediate/final components before every lookup/list/open/read instruction. Outside sentinel content must never be accessed or returned; an open old authorized inode preserves the reviewed drift semantics. §4.5 base descriptors, §4.13, R1/R8.

### AUD-29-63 — P2 — Some test and diagnostic failure paths can write disk-backed scratch

**Evidence: Source; inspected 2026-09-29.** [server target fixture](../../crates/server/tests/common/target.rs), target_dir; [fleet test tracer](../../crates/server/tests/common/trace.rs); [reference oracle configuration](../../crates/vfs/tests/reference_model.rs), around 67. | Priority / transfer | Measured quorum RTT and uncertainty tie behavior | Regional failure domains, representative selection, correlated RTT changes |
| Replication window | Core machinery and live window configuration | More than one append actually in flight to a live follower; no stalled session lending |
| Fast track | Implemented and researched | Keep it closed for the measured leader-origin workload unless new evidence reverses the decision |
| Multilog | Research/model exists | Do not enable extra logs without a workload and measured net improvement |
| Warm retention / reviewed quorum-loss recovery | Implemented mechanisms | State/admission limits, complete transfers, fresh identity after total state loss |

The ledger records a pipeline wired on 2026-09-29, so “no pipeline exists” would be wrong. The unresolved question is whether the live endpoint ownership/round lifecycle permits the core to use its window effectively under WAN conditions. Count actual sent-ahead batches and concurrent append flights on the daemon; a configured window or passing pure-core test is insufficient.

### 4.2 Raft improvements in priority order

1. **Close term/index/epoch exhaustion and recovery validation first.** AUD-29-26 is an actual safety counterexample. Extend bounded histories to direct boundary seeds, snapshot/install, fast-window recovery and retained membership.
2. **Separate control cadence from object backlog.** AUD-29-28 is the highest liveness priority. Election parameters derived from RTT are meaningless if application work delays the timer drive by an unrelated amount.
3. **Make live follower progress ownership explicit.** One session has bounded, prioritized concurrent exchanges now. Replace exclusive whole-endpoint lending with a bounded peer/session owner serving requests by class. Keep one authoritative progress state per follower; late success/refusal/snapshot replies must not regress it.
4. **Measure effective replication flow control.** Bound bytes and messages in flight per follower using admitted memory and measured BDP, not a batch count alone. Distinguish probe, replicate and snapshot progress so a rejected probe or lost snapshot cannot wedge a follower.
5. **Bound snapshot and configuration publication end to end.** An entry batch cap does not bound a whole configuration snapshot. Build, encode, send, verify, install and retain it in cooperative admitted slices; measure catch-up during ongoing configuration changes.
6. **Retain membership failure-domain intent.** Regional voters and root representatives must be eligible, live, caught up and appropriately placed. The existing “root representatives chosen by id order” gap is important. Optimize measured quorum RTT subject to that intent; lowest id is not a fault-domain policy.
7. **Backpressure uncommitted configuration work.** Compaction removes committed prefixes. It does not bound a minority leader's uncommitted tail or the memory consumed by learners and repeated proposals. Refuse before an admitted budget is exceeded; preserve typed caller retry.
8. **Keep publish-before-ack exact.** Optimize AUD-29-30 only with crash/restart oracles that retain term, vote, committed prefix, snapshot, configuration and accepted windows together.
9. **Audit every takeover against the register invariants.** Couple council decisions to the existing TotalOrder, Continuity, StaleNeverCommits, ReadSafety and NoLoss history checks. A stable failure-detector belief is availability evidence; it is not permission to lose fencing history.
10. **Benchmark the real decision workload.** Keep one log for leader-origin configuration commands unless the multilog record changes. Keep fast-track enablement based on the recorded workload/loss crossover. Do not advertise a research mechanism as an unconditional WAN speedup.

No new coordination service, global per-file index or consensus-on-write path is proposed.

### 4.3 Scaling risks beyond consensus

**Formation and peer ownership.** The direct-contact rule in [fleet.rs](../../crates/server/src/fleet.rs), around 3980, includes bounded neighborhoods, voters and staged peers, which is appropriate. Formation contacts everyone and peer tasks are created from the roster. The API/source distinction matters: bounded steady active contacts does not prove bounded total task/roster/socket memory or safe simultaneous restart traffic. Count dormant tasks and partially formed sessions too. At fleet size N, all-to-all formation can create O(N²) attempted relationships.

**Placement and the source of a remote attach.** Current archive restoration is eager. A metadata-only attach followed by lazy content lookup is still owed, as [restore.rs](../../crates/archive/src/restore.rs) itself states. Remote content has to be verified, admitted, bounded and served without copying the whole volume before it can attach. The design's source directory can be enormous precisely because only loaded state should cost RAM.

**Failure domains and repair amplification.** f+1 copies protect the declared host-failure model, not automatically rack, zone or region loss. Candidate selection must encode failure-domain constraints. Measure concurrent owners failing, correlated holder loss, repair traffic, lost-copy detection, scatter/copyset overlap and memory needed to repair while existing promises remain live. Placement shortfall must refuse or degrade explicitly, never quietly lower durability.

**Routing and identity churn.** Id-routed ownership is the correct starting point. Location hints, moved homes, retired incarnations, membership maps, pending handshakes, completion records and forwarding retries all need derived retention bounds. Whole-RAM replacement and overlap of old/new identities are explicitly open in [TBD_FIXES.md](../wip/TBD_FIXES.md). A late authenticated old announcement must not undo a new identity/location.

**Hot objects.** A green volume has one serialization owner; Meta-scale aggregate throughput does not imply unbounded throughput for one shared green. Measure conflict-heavy submit, rebase and metadata histories on that owner. Bound admission and report pressure while preserving deterministic order.

**Leases and clocks.** Keep leases tied to clock-domain and observed confirmation evidence, not a cached belief that can outlive a pause. The working tree includes active lease repairs. This audit does not claim those repairs passed. Re-run stopped-owner, stopped-successor, delayed-message, changed-cohort, joint-configuration and ordinary latest-read histories with those edits.

**Network service classes.** Priority labels alone cannot guarantee control latency if receive parsing, decryption, reconstruction, session ownership or executor steps share an unbounded bottleneck. Test class isolation at every stage, including packets from an authenticated peer whose bulk demand exceeds admission.

The driver mirrors Endpoint's flattening and raw fragmentation. It compares public certificate DER inside the reconstructed payload, printing only the result. It does not print a private key, bypass certificate authentication, or claim an established encrypted payload is plaintext.

#### 7.4.3 Congestion bytes and a fitting control frame

~~~rust
use slates_transport::connection::{Connection, ConnectionShape, Priority, Role};
use slates_transport::endpoint::PACKET_OVERHEAD_BYTES;
use slates_transport::packet_number::{encode_packet_number, MAX_PACKET_NUMBER_BYTES};
use slates_transport::session::Frame;
fn main() {
  let shape = ConnectionShape::for_frame_cap(1200, 48_000_000);
  let mut tiny = Connection::new(shape, Role::Client);
  tiny.seed_rtt(1_000_000, 0);
  let (mut packets, mut upper_bytes, mut protected_bytes) = (0, 0usize, 0usize);
  for _ in 0..1000 {
    tiny.open_exchange(1, Priority::Control, b"x").unwrap();
    if let Some((pn, frames)) = tiny.poll_transmit(0, 64) {
      packets += 1;
      let frame_bytes: usize = frames.iter().map(Frame::encoded_len).sum();
      upper_bytes += frame_bytes + PACKET_OVERHEAD_BYTES;
      protected_bytes += frame_bytes + PACKET_OVERHEAD_BYTES
        - MAX_PACKET_NUMBER_BYTES as usize + encode_packet_number(pn, None).len();
    }
  }
  println!("tiny_packets={} payload_inflight={} accounted_datagram_bytes={} window={}",
    packets, tiny.bytes_in_flight(), upper_bytes, tiny.congestion_window());
  println!("calculated_protected_bytes={}", protected_bytes);

  let mut tail = Connection::new(shape, Role::Client);
  tail.seed_rtt(1_000_000, 0);
  let bulk = tail.open_exchange(2, Priority::Bulk, &vec![0; 11_000]).unwrap();
  for step in 0..20u64 {
    let now = step * 1_000_000;
    if tail.poll_transmit(now, 1200).is_some() {
      tail.handle_incoming(now, 1_000_000 + step, &[
        Frame::MaxData { max: 1_000_000 },
        Frame::MaxStreamData { stream_id: bulk, max: 1_000_000 },
      ]);
    }
  }
  let control = tail.open_exchange(1, Priority::Control, b"x").unwrap();
  let sent = tail.poll_transmit(100_000_000, 1200)
    .is_some_and(|(_, frames)| frames.iter().any(|frame|
      matches!(frame, Frame::Stream { stream_id, .. } if *stream_id == control)));
  println!("window_tail: inflight={} window={} spare={} tiny_control_transmitted={}",
    tail.bytes_in_flight(), tail.congestion_window(),
    tail.congestion_window() - tail.bytes_in_flight(), sent);
}
~~~

## 8. Recommended order of work

1. Close grant binding and exact-snapshot landing, target authority and outsider deletion safety. These decide whether the product is permitted to touch a user's disk at all. Establish the strict RAM and access contract in §9; ordinary pageable success cannot certify it.
2. Close runtime/mapping soundness, allocator validation and identity exhaustion. Otherwise all higher-level test results rest on unsafe foundations.
3. Close handshake protection, content authority, per-key limits and unauthenticated admission. An enrolled host or a content hash must not confer unrelated consumer rights.
4. Admit every archive/wire/holder representation; make references idempotent and retain the acknowledged closure before replying. Fence incomplete recovery and preserve exact policy, metadata and sparse state.
5. Make SDK admission/completion/cancellation and MCP service terminal, bounded and honestly async. Keep an owning transport driver progressing while application operations await.
6. Correct packet-byte accounting, window-tail selection and retransmission priority before repeating network comparisons. Derive control headroom from the actual failure and workload budgets.
7. Prove live Raft/register progress, bounded retention and laptop/fleet equivalence through the product. Then measure the transfer and constrained-network experiments in §§10–12 against their corrected baselines.
8. Establish current capability truth and the missing ratchets/platform/scale evidence. No benchmark result can waive an isolation, authorization or acknowledged-state defect.

No implementation defect is closed by this document. Findings must become failing behavioral tests, minimal design-consistent repairs, and sibling sweeps. Existing gaps remain open until their actual acceptance contracts pass.

## 9. Strict RAM isolation: define and prove the entire boundary

### 9.1 The requested guarantee is stronger than the observed implementation

Four different claims need independent evidence: no unauthorized host-file access, no private pageout/dump, no unauthorized disclosure across consumers or hosts, and bounded ownership through cancellation/recovery. Passing one does not imply the others. AUD-29-01, 08–18, 31, 35–36 and 41–46 already prevent a complete claim; AUD-29-59 and 62–63 add retention, containment and test-harness boundaries.

R1 permits read-only access to the declared base and a granted landing. Ada's literal “DO NOT allow disk access” is stricter. The current product reads host bases; CLI fleet bootstrap reads certificate/manifest files and resolver configuration, and recovery-key input can read a file. Those are real access paths, even when they do not write private overlay bytes. See [Unix base](../../crates/base/src/unix.rs), [Windows base](../../crates/base/src/windows.rs), [fleet bootstrap](../../crates/cli/src/fleet.rs) and [recovery-key input](../../crates/cli/src/recovery_key.rs). The audit does not silently grant an exception. A deployment claiming literal zero disk access must supply its authorized inputs as retained RAM capabilities and prove the complete process access boundary; the present base/bootstrap behavior cannot certify that claim. The design-sanctioned base and landing effects must otherwise be named explicitly in the claimed contract. This is a contract discrepancy to resolve, not permission to add a mode switch or a legacy path.

OS facts read through a kernel virtual filesystem are a different effect from reading a regular disk file. A path spelling such as /proc, /dev/shm or a configured scratch name does not establish that distinction by itself. The test must identify the backing object and platform behavior. Builds and edits made to produce this review are development artifacts; the bounded diagnostics did not demonstrate a hermetic deployed lifecycle.

| Representation or boundary | Observed assurance / gap | Evidence needed for strict acceptance |
|---|---|---|
| VFS extent arena | Strict create attempts to lock this arena; ordinary create defaults otherwise | Protected capacity prepared before create; refusal before publication; exact locked/usable charges and strict p99 provisioning |
| Inline content, names, metadata, attributes and inode versions | Separate heap/slab allocations; private state exists outside extent bytes | Admitted protected ownership for both bytes and metadata, including copies and retained versions |
| SDK/IPC requests, replies and completion records | Shared-memory backing is pageable; locking a content arena does not lock rings | Residency and dump policy in each owning process; destination admission before copying; terminal release on channel loss |
| Database, green histories, anchor images and holder closures | Different retention owners; remote holders are process-local | Publication-before-ACK and complete warm recovery in protected anchor RAM; refuse shortened/incomplete acknowledged state |
| Archives, codec scratch, TLS and retransmission buffers | Whole-message Vecs and intermediate decoded content | Simultaneous peak reservations for encoded, decoded, verified and retransmittable representations; no uncharged second copy |
| Mount/client/guest page caches | Outside the daemon arena; guest/open-reference cost is already owed | A platform-specific supported boundary for workload and guest caches; actual cache residency evidence or typed inability to promise it |
| Standard streams, crash output and diagnostics | Descriptor-number exemptions allow regular-file sinks; no dump-exclusion policy found | Verify the actual sink; forbid private data in unapproved output; demonstrate dump exclusion, including child/anchor processes |
| Base lookup and later reads | Unix retains descriptor-relative roots; Windows re-resolves paths | Authority tied to the opened object at every step; outsider replacement oracle; never access an outside sentinel |
| Fleet content and dedup | Host identity and hash currently suffice for global-holder queries | Per-consumer authority checked before lookup/receive/fetch, revocation at use, scoped existence/timing oracle |
| Destroy, revoke, reconnect and restart | Freeing an object is not evidence that all copies or stale handles disappear | Owner ledger across every representation; stale-access rejection, cancellation drain, dump/pageout policy and reuse isolation |

No swap, core dump or cross-consumer read was deliberately induced in this audit. These are unclosed guarantees supported by the allocation/access paths, not fabricated observations of a leak.

### 9.2 Admission must cover simultaneous costs and every lifecycle

The §4.2 accounting obligation is per host, including outstanding promises. For a workload history, the required reserved capacity is the peak simultaneous sum of protected live content, retained snapshots/green versions, manifests and indexes, metadata, open references, rings, logs/completions, TLS/transport state, retransmission ownership and codec/restore scratch. Dedup reduces unique byte ownership; it does not eliminate manifest/reference metadata, the receiver's transient verification copy, or a sender's retained retransmission source. A mapped address-space size is not physical capacity.

Charge before allocation or ownership transfer, then publish only after all required reservations and authority checks succeed. A refusal at any step must leave observable state and every charge unchanged. Credit returned to a network sender must correspond to an admitted destination, rather than consumption into an ever-growing heap buffer. On a cross-host put, sender-side admission does not reserve the holder's capacity. Only a complete, independently verified, retained closure can be ACKed as placed.

Exercise each operation at every acquisition boundary: create, copy-up, xattr growth, clone, snapshot, seal/export, compression, offer/put/fetch, merge input retention, remote attach, takeover, destroy, resize and landing plan creation. Race cancellation with publication and completion, then spend the released capacity from a different volume. Count private retained bytes after all owners terminate. Test the anchor's survival separately from whole-anchor loss, and the guest/workload owner separately from the daemon. Do not add per-item locks or external-runtime ownership to solve these obligations.

### 9.3 The isolation oracle must observe authority as well as location

The existing source-string wall and trace classifier are useful tripwires, but neither is the promised linkage/effect proof. An adequate observation records the real object, operation, consumer, grant/fence, approved state and time. A landing-target prefix is insufficient: an authorized target can still receive a write before permission, after revocation, from the wrong consumer, or through a replaced directory. A hidden sibling's name cannot confer authority.

Separate a no-grant lifecycle from an explicitly granted landing lifecycle. Include startup, certificate/base acquisition, full usage, cancellation, restart, teardown and failure output. Trace reads as well as writes where the claimed access contract requires it. Audit imported libraries and error branches, then match trace evidence to supported process/platform residency evidence. An unavailable tracer, unsupported dump policy or unverified RAM scratch produces an explicit gap; it cannot close R1 through a skip. The observer itself must not persist private samples to disk.

## 10. Sophisticated file-transfer scenarios and measured optimization candidates

The implementation already has content identities, chunk dedup, per-holder missing sets, bounded export slices, compressed chunks, placed-before-reference logic and persistent sessions. The opportunities below extend those mechanisms. None justifies a second protocol path, unrestricted shared cache, global catalog, per-write consensus, inferred merge or a new tuning constant. Correctness repairs in findings 43–59 precede performance comparisons.

### 10.1 Avoid work and bytes that the receiving operation does not need

| Scenario | Current cost or missing evidence | Candidate using the existing design | Required comparison / oracle |
|---|---|---|---|

An archive identity cannot provide a complete-state optimization until omitted metadata is fixed. Likewise, zero-filled content dedup is not sparse restoration, and a small missing-set response is not proof that interrupted partial bytes were preserved.

### 10.2 Compression must minimize the receiving operation's total cost

[Codec policy](../../crates/server/src/config.rs) currently derives the byte-worth decision from the machine profile. That supports a measured local storage decision; it does not establish the best tradeoff for a constrained link or a heterogeneous recipient. A comparison needs compression CPU, receiver decompression CPU, admitted scratch, encoded wire bytes, effective available goodput, extra round trips, class deadline and the receiver's verified codec support.

A useful experimental estimate is `CPU_encode + CPU_decode + wire_bytes / available_goodput + added_round_trip_cost`, with queue and scheduling time measured separately. Compare raw and encoded representations under identical chosen-content and authority checks. Account for already cached representations and all recipients; a fast sender can overrun a slow decoder, and an incompressible/encrypted file can pay CPU for no wire saving. The estimate is an experiment input, not permission to make a fixed threshold a product policy.

Include text, binaries, random/encrypted content, small files, repeated chunks, sparse data and already-compressed archives. Dictionaries or cross-object compression must remain within the permitted sharing scope; they must not disclose another consumer's bytes/existence. A dictionary must have bounded retained ownership and a verified identity. Any format change follows the design amendment and canonical/golden-vector process; no opportunistic alternate format is accepted by this audit.

### 10.3 Copies, syscalls and CPU become different bottlenecks across the envelope

Measure separately the source snapshot view, export chunk, encoded archive, per-recipient body, StreamSender storage, retransmission frames, packet encryption buffers, received body, decoded archive, verified holder and restored volume. “Zero copy” is unsubstantiated while those Vec clones remain. Encrypted traffic still needs authenticated packet processing; immutable handles can avoid extra ownership copies without pretending that cryptography or verification disappears.

On fast local links, measure packet batching/completion costs and cache behavior through the existing platform driver seams. On thin links, per-object envelope and unnecessary round trips can dominate. On high-RTT links, enough admitted pipeline ownership is necessary to fill the usable path; unbounded prefetch is prohibited. On a laptop under CPU pressure, codec/manifest work must yield before heartbeat and ring service deadlines. Record instructions, allocations/copies, protected peak RAM, encoded bytes and shard-step tails alongside goodput.

Prioritize outcomes in order: complete authorized state, protected bounded retention, time to the first useful operation, whole placement/takeover latency, and sustained useful goodput without harming control or other flows. A high aggregate byte rate achieved by resending content or filling a slow client's buffer is not an optimization.

### 11.1 What the current network evidence establishes

The [constrained-link research](../wip/research/nfs-transport-constrained-links.md), [fleet-transport contract](../wip/research/fleet-transport.md), [benchmark record](../wip/BENCHMARKS.md) and live sources were inspected on 2026-09-29. The September 28 selection keeps Copa and strict fresh-stream priority; rejected controllers/schedulers were deleted. The historical decision reported Copa's goodput-shortfall geomean 1.068, worst ping-p99 ratio 3.05 against the best law, and rejected the Meta δ=0.04 experiment with RTT-fairness Jain 0.840. Those are recorded comparisons under that harness, not performance guarantees on every network. This audit does not propose reintroducing the rejected paths.

The current [congestion benchmark](../../crates/transport/examples/congestion_bench.rs) has a 48-case rate/RTT/random-loss grid and eight added cases, hence **56 scenarios**. The historical five-law bake-off's **57** included CUBIC coexistence; the chosen-controller harness is not the same coverage claim. Verification used Python csv.DictReader and filtered seed.isdigit(); the input was limited to less than 2,000,000 bytes. This is evidence inventory, not a newly executed benchmark.

Correct AUD-29-50 accounting before treating any old controller ratio as a current baseline.

### 11.2 Respect the physical lower bounds and optimize avoidable costs

Serialization time is `8 × datagram_bytes / available_bits_per_second`; queued bytes add the same unavoidable cost. A 1,200-byte datagram takes **150 ms at 64 kbit/s**, **600 ms at 16 kbit/s** and **1.2 s at 8 kbit/s**. Two such datagrams serialize for 300 ms, 1.2 s and 2.4 s respectively. These are calculations, not observations. Smaller protected control packets have smaller costs; the current endpoint does not pad every ordinary control packet to 1,200 bytes.

The controller's initial ten-datagram window and two-datagram minimum make packet size/queue occupancy especially consequential below one packet per RTT. The ten-datagram window would require 1.5 s of serialization at 64 kbit/s or 12 s at 8 kbit/s if fully queued; this is not a claim that pacing actually emits that whole burst. Preserve the congestion/security laws while measuring a finer pacing release and queue occupancy. RFC 9002 distinguishes its minimum/initial windows, pacing and ACK-only traffic; an experiment must retain the applicable boundaries. [RFC 9002 §§7.2, 7.7 and Appendix B](https://www.rfc-editor.org/rfc/rfc9002.html#section-7.7).

An operation's completion lower bound includes required causal round trips, indispensable authorized bytes divided by available goodput, verification CPU, and service/queue delays. Placement still needs the required number of complete retained holders; a latest read still needs its read-safety proof. When the path/fault budget makes those guarantees unavailable, return the declared typed unavailable outcome. A pinned already-retained read can use its own existing semantics; it must not be presented as a successful latest read or durability ACK.

Therefore prioritize removing avoidable round trips and bytes, recovering only missing verified progress, scheduling urgent eligible packets before queued bulk, and preventing local work from wasting a usable network interval. Increasing buffers or retry frequency cannot increase a link's physical capacity. Avoid a reconnect/handshake storm during an outage and an unconstrained bulk burst when it clears. The caller's operation/completion identity survives retry; every late result has an owner.

### 11.4 Stress matrix the existing grid does not supply

Build bounded deterministic fixtures in the existing Rust simulator before authorized platform/network runs. Fixture values describe experiments, not production defaults. Extend from the current minimum rate by powers of two; extend RTT until required operations become physically unavailable; vary each direction independently. Sweep outage length around the actual derived retry, suspicion, takeover and operation deadlines. Include outages shorter and longer than each, rather than assuming one chosen delay exercises them all.

Combine thin bandwidth with high RTT, heavy bulk loss, constrained ACK return, reverse application traffic, a slow codec CPU, exhausted holder admission and an unrelated local SDK workload. Add repeated capacity collapses, PMTU shrink/blackhole, reordering beyond the existing ±8 ms case, duplicate old flights, queued resets, FIN/ACK loss and authenticated address change. Test one session, multiple sessions to one peer, and many peers behind one host uplink. A two-flow Jain score cannot certify fairness across thousands of consumers.

For every case report useful verified goodput; time to first useful read; control/metadata/bulk p50/p99/p999/max; whole place/attach/takeover time; per-direction protected bytes and overhead; queue occupancy/time; retransmitted/hedged/discarded bytes; credit/window/pacer stalls; largest shard step; heartbeat gaps/elections; peak protected and transient RAM; refusals and cancellation/recovery outcomes. Keep stalls and unavailable outcomes in the report. Excluding them from latency percentiles would hide the worst networks the user specifically asked about.

## 12. End-to-end, integration and scale acceptance gaps

### 12.1 Existing tests are substantial; their composition is incomplete

The register and Raft cores already exercise quorum/fences, retries, joint membership, learners, snapshots/compaction and pipeline behavior. The [fleet integration fixture](../../crates/server/tests/fleet.rs) covers real peer sessions, remote reads/forwarding, owner loss, content repair, placement-before-reference, slow-holder hedging and warm root/regional recovery. [Transport exchanges](../../crates/transport/tests/exchanges.rs) cover multiplexing, cancellation/quiescence, loss/reordering and session admission. VFS oracles and bridge conformance provide valuable independent legs. This audit's six holder and four Copa tests passed.

Those results do not cover the new failing witnesses or the combined strict-RAM/full-filesystem/network contract. Small byte payloads and quorums surviving restart cannot stand in for complete archived metadata, sparse retention or remote holder publication. A clean-path priority exchange cannot stand in for real control behind lost bulk and an awaited handler. An N=1 register differential does not prove N=1 filesystem/SDK/bridge equivalence. Platform builds and loud skips are honest limits, not executable evidence for the skipped behavior.

The following case labels are local audit labels, **not new design T/AC identifiers**. Implementations must cite the relevant existing criteria without renumbering them. Each case needs a behavioral failing witness before the repair, an independent expected outcome and non-vacuity evidence that the intended boundary actually ran.

### 12.2 Scale must include admission, scheduling and failure costs

Progress from one host/one shard, through multiple local shards and f=0, to f>0 regional cohorts and root/regional configuration groups with independent fault domains. Carry the same generated histories and authority/refusal oracles throughout. Vary loaded and untouched files independently: a billion-file base is not a billion-loaded-inode workload, and a lazy base must not make a small request enumerate unrelated entries. Include deep/wide directories, hot greens, many cold greens, pinned old versions, many peer sessions and concurrent users.

Derive each simulation size and seed/work budget from available RAM and a stated operation bound. Run real-process/platform cases only in their authorized existing gated environments. Use the existing Rust simulator, reference seams and jobs; no new model-checking tools, runtime, installs or background jobs follow from this document. This audit did not launch any of those scale runs.

For a laptop, keep the existing 1/8/64-client provision sweep and distinguish spinning/parked and oversubscribed informational runs. The strict protected contract must be included, not hidden behind the ordinary pageable default. For a fleet, measure metadata and configuration bytes per host/group, useful record/content pipeline occupancy, p99/max per-shard step, election/takeover time, repeated repair traffic, warm publication/recovery cost and peak retained/transient bytes. Increase unrelated objects and peers while holding one operation's useful work constant; growth reveals hidden full-state scans, copies or barriers.

Exercise CPU and scheduler pressure as well as network pressure. The concurrent KIND record already reports heartbeat lapses and daemon restarts under an idle five-replica WAN-profile fleet; that remains an open integration signal in GAPS, not a healed defect because richer heartbeat logging exists. Core consensus tests with timely polling cannot rule out that production scheduling failure. Record host scheduling, actual timers, heartbeats and state publication together.

Capture release commands, revision, hardware/OS, workload/dataset identity, load discipline, every seed/run, refusal/stall outcomes and the harness's noise floor. Compare a corrected baseline and one candidate under identical conditions. Microbench best-of-N results cannot establish tail latency for a congested product, and normalized throughput cannot hide a missed safety or durability oracle.

### 12.3 Closure requires the missing behavior, not a larger passing count

Keep all 63 findings open until their independent regression fails on the defective path, the design-consistent repair lands, sibling instances are swept and the applicable integration/platform gate passes. For source-only findings, first build the smallest behavioral witness through the existing seam; internal probe outputs in §7 are diagnostics, not substitutes for R5 acceptance tests. Prove cancellation, refusal and recovery beside the successful operation.

Close RAM isolation only with complete supported-platform/process evidence, not a locked flag or a permitted trace prefix. Close placement only with exact retained state after the promised failures, not an ACK count. Close network performance only with useful goodput and control tails under the real shared-resource path, corrected protected-byte accounting and bounded memory. Close R8 only with the complete product differential. Skipped or LIMITED lanes remain visible and cannot silently expand a capability claim.
